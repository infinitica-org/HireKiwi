## 5.1 The Agent Paradigm in SmartZen

Verification in SmartZen is not a static form-checking exercise or a passive cron job. It is driven by **autonomous intelligent agents**, led by **Vivi**—the flagship **Source Verification Agent**.

In legacy recruitment, candidate claims (resumes, portfolios, listed skills) are accepted on faith or subjected to manual, error-prone background checks weeks after an offer is extended. SmartZen inverts this model: **unverified claims are never elevated to talent intelligence without source-level verification**.

The core doctrine of SmartZen agents is:
> **"Verify at the source. Trust zero self-declared assertions. Ground every skill in immutable cryptographic provenance."**

## 5.2 Meet Vivi: Flagship Source Verification Agent

**Vivi** is the primary autonomous verification agent deployed across the SmartZen platform. Vivi's sole mission is to **interrogate, validate, and certify talent data directly at its authentic source** before that data can influence a candidate's evidence-backed talent profile.

### Core Architectural Characteristics of Vivi:
- **Event-Driven Execution:** Runs on distributed BullMQ worker pools, responding asynchronously to evidence submission events (`evidence.submitted.v1`).
- **Sandboxed Outbound Connectors:** Communicates with external identity providers, git hosts, credential authorities, and institutional databases through rate-limited, egress-filtered security sandboxes.
- **Cryptographic Attestation:** Emits tamper-evident, HMAC-SHA256 signed verification tokens containing source URI, digest hash, validator timestamp, and confidence rating.
- **Continuous Provenance Monitoring:** Periodically re-verifies public repositories and credential endpoints to detect post-verification repository deletions, commit re-writes, or certificate revocations.

## 5.3 Vivi's Four Autonomous Source Verification Protocols

Vivi executes four specialized source-verification protocols corresponding to the four primary evidence categories in the SmartZen evidence graph:

```
                          ┌────────────────────────┐
                          │   VIVI AGENT ENGINE    │
                          └───────────┬────────────┘
                                      │
         ┌────────────────────────────┼────────────────────────────┐
         │                            │                            │
         ▼                            ▼                            ▼
┌─────────────────┐          ┌─────────────────┐          ┌─────────────────┐
│ 1. ACADEMIC     │          │ 2. CODE & AST   │          │ 3. WORK &       │
│    SOURCE       │          │    PROVENANCE   │          │    ENDORSEMENT  │
│    (SIS / ERP)  │          │    (GitHub API) │          │    (Corp Domain)│
└─────────────────┘          └─────────────────┘          └─────────────────┘
         │                            │                            │
         └────────────────────────────┼────────────────────────────┘
                                      ▼
                             ┌─────────────────┐
                             │ 4. CREDENTIAL   │
                             │    AUTHORITY    │
                             │    (Credly/AWS) │
                             └─────────────────┘
```

### 1. Academic Source Verification Protocol (`UNI-02`, `INTG-01`)
Vivi verifies student enrollment, academic standing, and departmental affiliation directly at the institutional origin:
- **Direct SIS/ERP Connector (`INTG-01`):** Interrogates institutional registrar systems (Banner, PeopleSoft, Canvas, or campus ERPs) via secure API or scheduled batch sync.
- **Whitelisted Domain Assertion (`UNI-02`):** Validates that candidate authentication maps to an approved institutional domain (`@university.edu`) whitelisted by the university administrator (`FR-UNI-02.01`).
- **Data Integrity Check:** Matches student roll number, graduation year, degree program, and verified CGPA against registrar records without exposing student data to public networks.

### 2. Code Repository & AST Technical Provenance Protocol (`VER-04`, `INTG-02`)
When a student links a GitHub or GitLab repository to support a software engineering claim, Vivi inspects the repository directly at the source:
- **Authorship Verification (`FR-VER-04.04`):** Connects to GitHub REST and GraphQL APIs. Evaluates git commit author emails against the candidate's verified identity, checking GPG/SSH commit signatures and commit timestamp distribution.
- **Contribution Ratio Thresholds:** In collaborative repositories, Vivi verifies that the candidate authored at least **35% of non-boilerplate commits** and **40% of core business logic lines of code** (`FR-VER-04.03`).
- **AST Complexity & Scaffolding Analysis (`FR-VER-04.05`):** Parses the Abstract Syntax Tree (AST) of nominated codebases. Calculates Cyclomatic Complexity, Halstead volume, and modular coupling.
- **Tutorial & Plagiarism Scanners:** Cross-references repository AST fingerprints against known open-source tutorial repositories (e.g., TodoMVC, freeCodeCamp clones) and internal repository indexes. Identical tree structures without attribution trigger immediate rejection.
- **Queuing for Defense (`FR-VER-04.07`):** Once repository provenance is confirmed, Vivi automatically schedules the project for the AI project defense interview (`INT-01`).

### 3. Work Experience & Corporate Endorsement Protocol (`VER-02`)
To eliminate fraudulent offer letters and falsified internship claims, Vivi enforces a corporate domain-verified endorsement protocol:
- **Document Categorization (`FR-VER-02.01`):** Inspects uploaded documents. Offer letters and appointment letters are classified as `INVALID_DOCUMENT_TYPE` and rejected; only relieving letters or verified completion certificates are accepted.
- **Corporate Domain Validation (`FR-VER-02.06`):** Interrogates the endorser's email address against MX records and known corporate domain registries. Public webmail providers (`@gmail.com`, `@yahoo.com`, `@outlook.com`) are mechanically blocked for corporate claims.
- **Cryptographic Token Dispatch (`FR-VER-02.03`):** Generates a single-use, cryptographically signed verification link with a strict 72-hour time-to-live (TTL).
- **Anti-Collusion & Endorsement Ring Detection (`FR-VER-02.10`):** Vivi analyzes submission metadata (IP subnet, browser fingerprint, timestamp clustering, and cross-endorsement reciprocity). If two students mutually endorse each other from identical IP addresses, Vivi flags the case as a suspicious collusion ring.
- **Automatic Invalidation & Recalculation (`FR-VER-02.11`, `FR-VER-02.12`):** If a reviewer or corporate manager invalidates an endorsement, Vivi instantly revokes the verified status and triggers automated recalculation of all affected skills and competencies.

### 4. Credentials & Certification Authority Protocol (`VER-03`)
Vivi interfaces directly with external certification issuers:
- **Authority API Interrogation (`FR-VER-03.04`):** Connects to verified issuer APIs (Credly Acclaim API, AWS Certification Registry, Google Cloud Certified Directory, Coursera Partner API) using official credential IDs (`FR-VER-03.03`).
- **Anomaly Detection (`FR-VER-03.06`):** Detects expired credentials, duplicate submissions across multiple candidate accounts, and mismatched recipient names.
- **Taxonomy Linking (`FR-VER-03.09`):** Automatically maps validated certifications to corresponding skills in the SmartZen competency taxonomy with pre-calibrated baseline proficiency ratings.

## 5.4 Vivi's Verification State Machine

Every piece of submitted evidence transitions through Vivi's formal state machine:

```
               ┌────────────────┐
               │   SUBMITTED    │
               └───────┬────────┘
                       │ Event: evidence.submitted.v1
               ┌───────▼────────┐
               │ VIVI_INSPECTING│
               └───────┬────────┘
                       │ Outbound Source Probe Dispatched
               ┌───────▼────────┐
               │SOURCE_CONTACTED│
               └───────┬────────┘
         ┌─────────────┴─────────────┐
   Proof Confirmed             Integrity Anomaly / Ambiguity
         │                                   │
┌────────▼────────┐                 ┌────────▼────────┐
│    VERIFIED     │                 │  MANUAL_AUDIT   │ (ADM-02 Queue)
└────────┬────────┘                 └────────┬────────┘
         │                                   │
         │                          ┌────────┴────────┐
         │                     Human Approves   Human Rejects
         │                          │                 │
         │                          ▼                 ▼
         └──────────────────► [ VERIFIED ]       [ REJECTED ]
                                                      │
                                                      ▼
                                                 [ APPEALED ]
```

### Verification States:
1. **`SUBMITTED`:** Student uploaded artifact or registered repository claim.
2. **`VIVI_INSPECTING`:** Vivi agent has claimed the BullMQ job and is parsing metadata and AST structures.
3. **`SOURCE_CONTACTED`:** Vivi has dispatched validation requests to the authentic external authority (SIS, GitHub API, corporate domain, Credly).
4. **`VERIFIED`:** Source proof received, cryptographic token validated, HMAC signature emitted.
5. **`MANUAL_AUDIT`:** Low confidence ($C < 0.65$) or anomaly flagged; escalated to human verifier operations (`ADM-02`).
6. **`REJECTED`:** Source contradicted claim, fraud detected, or endorser repudiated experience.
7. **`APPEALED`:** Student initiated formal dispute with supporting evidence (`FR-INT-01.11`).

## 5.5 Confidence Scoring Engine

In accordance with PRD principle 6.2 ("Explain everything") and `Glossary`, SmartZen strictly separates **Skill Proficiency** (what level of ability is demonstrated, Beginner to Pro) from **Evidence Confidence** (how trustworthy is the underlying evidence, $0.00$ to $1.00$).

Vivi computes Evidence Confidence ($C$) using a multi-factor formula:

```text
Confidence (C) = (w_source * S_source) + (w_crypto * S_crypto) + (w_freshness * S_freshness) + (w_depth * S_depth)
```

| Weight Factor | Metric | Criteria |
| :------------ | :----- | :------- |
| `w_source = 0.40` | **Source Authority (`S_source`)** | SIS/Registrar direct (1.0), Corporate Domain (0.9), Credly API (0.95), Self-hosted Git (0.5). |
| `w_crypto = 0.25` | **Cryptographic Proof (`S_crypto`)** | GPG-signed commits, HMAC tokens, SAML assertions (1.0); unsigned raw commits (0.4). |
| `w_freshness = 0.15` | **Temporal Freshness (`S_freshness`)** | Activity within 90 days (1.0), 1 year (0.8), >2 years (0.5). |
| `w_depth = 0.20` | **Demonstration Depth (`S_depth`)** | Multi-month commit history, passed AI project defense (1.0); single patch (0.3). |

- If `C >= 0.85`: Automatically transitions to `VERIFIED`.
- If `0.65 <= C < 0.85`: Verified with `SUPPORTED` tag; queued for optional spot-check.
- If `C < 0.65`: Automatically routed to `MANUAL_AUDIT` queue for human review.

## 5.6 Human-in-the-Loop Operations (ADM-02 & ADM-03)

In accordance with PRD Product Principle 6.3 ("Human in the loop") and Responsible AI Governance (`SEC-02.04`):
- **Verifier Operations Queue (`ADM-02`):** Human verifiers inspect items flagged by Vivi. The interface presents Vivi's AST telemetry, IP correlation reports, and endorser response history.
- **Mandatory Justification (`FR-ADM-02.01`):** Every manual approval, rejection, or override requires a documented reason code, recorded in the audit log.
- **Appeals Workflow (`FR-INT-01.11`):** Students can appeal a rejection within 7 calendar days. An independent reviewer evaluates the claim, and if sustained, Vivi re-indexes the profile.

## 5.7 Tamper-Evident Verification Audit Trail

All actions executed by Vivi and human verifiers append immutable records to PostgreSQL:

```sql
CREATE TABLE "VerificationAuditLog" (
  "id" UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  "evidenceId" UUID NOT NULL REFERENCES "Evidence"("id"),
  "agent" TEXT NOT NULL DEFAULT 'VIVI_AGENT',
  "action" TEXT NOT NULL, -- SOURCE_PROBED | VERIFIED | FLAGGED | OVERRIDDEN | REVOKED
  "sourceProvider" TEXT NOT NULL, -- GITHUB | UNIVERSITY_SIS | CORPORATE_DOMAIN | CREDLY
  "previousState" TEXT NOT NULL,
  "newState" TEXT NOT NULL,
  "confidenceScore" NUMERIC(4,3) NOT NULL,
  "rationale" TEXT NOT NULL,
  "cryptoSignature" TEXT NOT NULL, -- HMAC-SHA256 of payload + timestamp
  "ipAddress" INET NOT NULL,
  "createdAt" TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

Every verified badge generated by Vivi can be publicly resolved and cryptographically checked at `becomesmart.online/verify/{credentialId}`, guaranteeing unfakeable proof to enterprise employers.
