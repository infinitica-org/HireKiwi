## 30.1 PRD Glossary & Core Terminology

Authentic definitions synthesised from `smart.ai_PRD_Functional_and_Non-Functional_Requirements.xlsx` and platform foundations:

| Term | Enterprise Definition |
| :--- | :-------------------- |
| **HireKiwi** | The AI-powered evidence-backed talent network platform connecting universities, students, and employers. |
| **Agents** | Autonomous intelligent software actors executing verification, interviewing, inference, and matching. |
| **Vivi** | The flagship Source Verification Agent whose mission is to verify talent data directly at its authentic source (SIS/ERP, GitHub AST, corporate domain, Credly API). |
| **Evidence-Backed Talent Profile** | Consolidated candidate representation showing claim-level verification badges and cryptographic provenance. |
| **Evidence** | An immutable record supporting a profile claim, accompanied by source provenance, cryptographic digest, and audit history. |
| **Evidence Classes** | Standardized categorization of claim backing: `Self-declared`, `Source-verified`, `Assessed`, and `Human-reviewed`. |
| **Active Evidence** | Real-time demonstrations directly observed by the platform (proctored coding, project defense, AI interviews). |
| **Passive Evidence** | Pre-existing external artifacts (GitHub repositories, university degrees, corporate experience letters, certifications). |
| **Competency** | A defined, observable ability under a skill, scored against standardized Behaviorally Anchored Rating Scales (BARS). |
| **Proficiency** | Skill level from Beginner to Pro derived from evidence under versioned evaluation rules. |
| **Confidence** | Metric ($0.00$ to $1.00$) quantifying the volume, authority, and reliability of evidence supporting a proficiency rating; distinct from proficiency itself. |
| **Project Defense** | AI-led proctored interview where a student explains and defends code architecture and commits from a submitted project. |
| **Corporate Endorser** | External industry professional who confirms a student's work experience through a cryptographically signed, expiring corporate domain link. |
| **Whitelisting** | University administrator action establishing domains (`@university.edu`) or student rosters eligible to join the tenant. |
| **Tenant** | An organization (university, campus, or employer) whose data is isolated via Row-Level Security and Prisma middleware. |
| **Discoverability** | Candidate privacy setting controlling whether corporate employers can discover their profile in candidate searches. |
| **Opportunity** | Employer-initiated outreach invitation directly linked to an active job opening (`SRC-02`). |
| **Candidate Pipeline** | Standardized employer hiring stages: `Applied`, `Reviewing`, `Interviewing`, `Offered`, `Hired`, `Rejected`. |
| **Entitlements** | Plan-based usage quotas on active jobs, candidate searches, direct outreach messages, and recruiter seats (`BIL-01`). |
| **Trust Case** | Investigation of suspicious activity, collusion rings, or cheating reports, resolved with documented rationale by a reviewer (`ADM-03`). |
| **Impersonation** | Audited, reason-bound support session viewing the product as a user with write operations blocked (`ADM-04`). |

## 30.3 Error Code Catalogue

| HTTP Status | Error Code | Description | User Remedy |
| :---------- | :--------- | :---------- | :---------- |
| `401` | `SMART_401_AUTH_EXPIRED` | JWT bearer token has expired or is invalid. | Re-authenticate via institutional SSO. |
| `403` | `SMART_403_TENANT_FORBIDDEN` | User does not hold permissions within target organization tenant. | Contact campus or employer organization admin. |
| `403` | `SMART_403_QUOTA_EXCEEDED` | Employer has exhausted plan entitlement for jobs, searches, or messages. | Upgrade employer subscription plan (`BIL-01.06`). |
| `422` | `SMART_422_COMPETENCY_FLOOR` | Candidate does not satisfy mandatory competency floor for requisition. | Complete recommended practice project or defense. |
| `422` | `SMART_422_INVALID_DOCUMENT` | Uploaded file is an offer/joining letter rather than completion certificate. | Upload official relieving or internship completion letter. |
| `429` | `SMART_429_RATE_LIMITED` | Sliding window rate limit exceeded on search or API endpoint. | Back off requests for 60 seconds. |
| `503` | `SMART_503_INFERENCE_DEGRADED` | External LLM unavailable; deterministic fallback scoring active. | System operating in deterministic fallback mode. |

## 30.4 Core Event Catalogue (Redpanda / Kafka)

- `candidate.onboarded.v1`: Candidate claims profile and completes initial onboarding consent.
- `evidence.submitted.v1`: New repository, certificate, or work claim registered for verification.
- `vivi.source_verified.v1`: Vivi completes autonomous source verification and emits cryptographic token.
- `vivi.anomaly_flagged.v1`: Vivi detects AST plagiarism, endorsement collusion ring, or expired credential; dispatches to `ADM-02`.
- `defense.completed.v1`: Proctored AI project defense session concluded and transcribed.
- `capability.tier_assigned.v1`: New BARS tier (Gold/Silver/Bronze) assigned and HMAC signed.
- `match.generated.v1`: Match score computed between candidate and active job opening.
- `application.status_changed.v1`: Candidate advances or is rejected in recruiter pipeline (`APP-02`).
- `telemetry.purge_executed.v1`: Nightly DPDP purge script completes deletion of expired snapshots.
