# ADR-0017: Semantic Vector Matching with Deterministic AI Failover

| Field        | Value                         |
| ------------ | ----------------------------- |

---

## Context

Sprint 6 expanded the matching pipeline from rules-based shortlisting to semantic vector similarity matching. Two problems had to be solved simultaneously:

1. **AI Gateway reliability (Th6-I610):** The JD parsing pipeline relied entirely on the AI gateway to extract competency vectors from job descriptions. If the gateway timed out or was rate-limited, the entire placement pipeline stalled.

2. **Privacy-preserving vector matching (Th6-I611):** The vector similarity search was running over all candidates before applying privacy opt-out filters, which was both a performance waste and a potential privacy violation.

---

## Decision

### 1. Heuristic JD Fallback Extractor (Th6-I610)

A deterministic offline fallback (`jd-fallback-extractor.ts`) was added to `opening-jd-parse.service.ts`. When the AI gateway times out or returns a non-200 response, the service falls back to:

- `extractSkillsOfflineFallback()` — keyword-heuristic skill extraction from the raw JD text.
- `extract10TrackThresholdVector()` — maps extracted skills to deterministic threshold vectors for all 10 supported tracks.

The fallback produces vectors that are lower-fidelity than AI-extracted ones but guarantee the placement pipeline never stalls on AI unavailability. This is the concrete implementation of ADR-0005 (ai-failover) for the JD parsing path.

### 2. Vector Cosine Similarity Candidate Matcher (Th6-I611)

A new `VectorCandidateMatcher` service replaces the rules-based shortlisting for the vector search path. Key design decisions:

- **Privacy opt-out applied before scoring:** Candidates with `discoverableToEmployers: false`, `isDeactivated: true`, or `isHeld: true` are filtered out before any similarity computation, not after. This ensures excluded candidates are never ranked.
- **Cosine similarity over pgvector:** Standard cosine similarity is computed in the database via `pgvector` for efficiency.
- **`RadarCompetencyAxis` 5-domain breakdown:** Each result includes a radar chart breakdown across 5 competency domains for employer-facing visualization (not stored; computed on-the-fly).

---

## Consequences

### Positive

- JD parsing is resilient to AI gateway outages — placement pipeline is always available.
- Privacy opt-out is enforced structurally (filter-first, not filter-after).
- Employers receive richer matching signal (5-domain radar vs. single score).

### Negative / Trade-offs

- Offline fallback vectors are lower-fidelity; a `source: 'offline_fallback'` flag should be surfaced in the employer UI in a follow-up.
- `RadarCompetencyAxis` type is internal; it should be exported from `@smart/contracts` if employer frontend needs typed consumption.
- Vector similarity over large candidate pools can be CPU-intensive; a rate-limit guard on `searchStudents` is recommended.

---

## Alternatives Considered

| Alternative                           | Why Rejected                                                                        |
| ------------------------------------- | ----------------------------------------------------------------------------------- |
| Stall pipeline on AI timeout          | Unacceptable; TPO placement dashboards become non-functional during AI degradation. |
| Filter privacy opt-outs after scoring | Privacy violation risk; excluded candidates' vectors would still be compared.       |
| Single-score matching only            | Insufficient signal for employer differentiation of near-equal candidates.          |
