# Cryptographic Certificates & Verification

Legacy educational credentials rely on printed PDFs or static images that are trivially altered using basic desktop software.

## Canonical Signature Construction

When a candidate successfully completes all required cognitive levels, the backend constructs a deterministic payload containing only immutable identification parameters.

This string is passed through `crypto.createHmac('sha256', process.env.CERTIFICATE_HMAC_SECRET)` and persisted in `Certificate.signatureHash`.

```typescript
export function computeCertificateSignature(
  payload: CanonicalCertificatePayload,
  secret: string,
): string {
  const serialized = JSON.stringify({
    certificateId: payload.certificateId,
    candidateId: payload.candidateId,
    trackId: payload.trackId,
    tier: payload.tier,
    issuedAt: payload.issuedAt.toISOString(),
  });

  return crypto.createHmac('sha256', secret).update(serialized).digest('hex');
}
```

## Public Verification Portal (`apps/web-verify`)

The public verification endpoint (`GET /api/v1/verify/:certificate_id`) is open to any third-party employer without login friction:

1. **Server-Side Verification:** The backend recomputes the signature from canonical fields and returns `signatureValid: boolean`.
2. **Client-Side Defense-in-Depth:** The Next.js verification client validates the query parameter hash (`?hash=...`) against the returned payload to ensure in-transit response integrity.
3. **Automated Tamper Alert:** If the signature hash fails verification, the verification portal renders a prominent `[SECURITY_EVENT]` alert indicating that the credential has been tampered with or revoked.
4. **QR Code Resolution:** Every exported PDF carries a vector QR code encoding the verification link for instant mobile auditing.
